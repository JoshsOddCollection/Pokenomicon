# JSON Schema
- `id` - A unique id for each card. This is generated by the following formula: `{set_name}_{card_number}`. Example: `fossil_1` represents the first card from the Fossil set.
- `card_type` - The type of card. Can be either `Pokémon` or `Trainer`.
- `name` - The name of the card as listed on the top left of the card. If the card does not have a name, such as an energy card, it should be described as such (ex: `Water Energy`).
- `number` - The number of the card in the set. This can usually be found on the bottom right of the card.
- `artist` - The artist of the card artwork.
- `rarity` - The rarity of the card.
- `variants` - A list of card variants.
    - `id` - A unique id for each card variant. This is generated by taking the card id and appending an underscore followed by the number of the variant.
    - `variant` - The card variant. Examples include `1st Edition`, `Shadowless`, and `Unlimited`.
    - `uncorrected_error` - `true` if this card has an error that was never corrected, otherwise the field should not exist.
    - `notes` - Notes about the variant, such as production information or rarity.
- `error_variants` - A list of error variants.
    - `id` - A unique id for each error variant. This is generated by taking the card variant and appending an `_e_` followed by the number of the error variant.
    - `error_name` - A colloquial name for the error. The name of the error should include the name of the card to reduce confusion (ex: `Evolution Box Error Wartortle` instead of `Evolution Box Error`). If the error isn't unique enough to warrant a unique name, the name of the set should be included in the error name (ex: `Blue Stain Fossil Haunter` instead of `Blue Stain Haunter`). If possible, errors should be given unique names that can be easily identified in the community, even across sets (ex: `Sunbeam Bulbasaur` is more identifiable than `Obstruction Bulbasaur`). Since new errors can be found at any time and new sets may introduce new errors, we want to try to future-proof the names of the errors. Error names may change if a new error is introduced that causes disambiguity, but our aim is to avoid that whenever possible. If an error name changes, it will be noted in the database. If an error applies to multiple variants, then the variant name should be included in parentheses (ex: `Blue Butt Vulpix (1st Edition)` and `Blue Butt Vulpix (Unlimited)`). If an error occurs on specific text in the card, that text should be included in the name of the error so that it can be easily identified (ex: `Length Hickey Krabby` instead of `Black Hickey Krabby`).
    - `error_type` - The type of error. Examples include `Additional Ink`, `Printer Hickey`, `Design`, and `Obstruction`.
    - `error_side` - The side of the card affected by the error. Can either be `Front`, `Back`, or `Both`.
    - `notes` - An object/dict containing notes about the card.
        - `description` - A description of where the error occurs on a card and what it looks like. Never `null`.
        - `print_run` - Notes about the print run, such as how early or late into the print run the error occurred. `null` if information about the print run is unknown.
- `cameos` - A list of all Pokémon featured in a card. Excludes Pokémon whose names are in the name of the card. If there's a fossil cameo, the species is followed by the text ` (Fossil)`, for example: `Kabutops (Fossil)`.`null` if the field hasn't been filled out yet, or an empty list `[]` if the card contains no cameos.
- `animal_cameos` - A list of all animals featured in a card. `null` if the field hasn't been filled out yet, or an empty list `[]` if the card contains no animal cameos.
- `pokeball_cameos` - A list of all types of Poké Balls featured in the card. Poké Balls featured as emblems (such as on Potions) do **_not_** count. `null` if the field hasn't been filled out yet, or an empty list `[]` if the card contains no pokeball cameos.
- `is_first_art_appearance_for_language` - A boolean stating whether or not this is the first appearance of the artwork for the given language. `null` if the field hasn't been filled out yet.
- `id_of_first_art_appearance_for_language` - The id of the first appearance of the artwork for the given language. `null` unless `is_first_art_appearance_for_language` is `false`.

Each `id` field is _permanent_ once it is committed to the `main` branch. This ensures that we always provide backwards compatibility and prevents breaking changes when new cards/variants/errors are added to the database.
